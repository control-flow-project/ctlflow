# Container release 0.1.24

Published on 2026-10-23 for Linux amd64. The release contains four selectable
crossfire servers and one shared Knex maintenance image. It contains no fleet
image, site branding, provider credentials, domain fleet or research data.

Runtime source commit: `774de415a2b327fde1a7d5be5001737e01776e91`.
Build-source digest:
`5654753e2dc919318e6d88d8679e95dbdd019d055c4876a7b26ef1d9c92722ad`.
All four images contain the same management UI, Element and onboarding release
`0.1.24-91092feb27e0aa3b2993da07`. C# uses the pinned .NET 11 RC2 SDK/runtime;
Rust uses the pinned 1.98.1 toolchain. These are native selected implementations,
not fallback processes inside a container.

Host fleet attachment uses the public npm fleet/fleetd 0.1.24 packages and the
execution host's existing Codex or Pi installation/login. Both npm archives
match the current source build byte-for-byte and were installed from the public
registry. They were not republished.

## Access

All five authenticated immutable image pulls were verified. At publication the
GitHub packages were private, and anonymous registry authorization returned 401.
Until the package owner makes them Public, your GitHub account needs package
read access. Authenticate Docker on the host with a token granting `read:packages`:

```sh
docker login \
  ghcr.io \
  --username YOUR_GITHUB_USERNAME
```

Enter the token at Docker's password prompt, not in a chat, fleet configuration
or container environment. Registry credentials stay in host-side Docker storage.
Public package settings permit anonymous pulls; publication by itself does not
change visibility. The verification record states the observed access status.

## Immutable references

The namespace is `ghcr.io/control-flow-project/`. Each image also has version tag
`0.1.24`; use its complete immutable reference instead of `latest`.

| Image | Registry manifest digest |

| `crossfire-csharp-managed` | `sha256:561a058ec71775685ddbc15fea0c93afe02e2c051dcce516106c3b96bdcea917` |

For the default NativeAOT server and matching maintenance image:

```sh
export \
  CROSSFIRE_RUNTIME_IMAGE=ghcr.io/control-flow-project/crossfire-csharp-nativeaot@sha256:37dc1f30ac1cd7cdf9b1cefc2a8bc65a81a546e3f7842a742797daea4a187f42 \
  CROSSFIRE_MIGRATION_IMAGE=ghcr.io/control-flow-project/crossfire-migrations@sha256:254a215b8d7fbb6e8d82b1dfec3fe5d930f259ad35a75ee8ac6100e82982cf3c
docker pull \
  "$CROSSFIRE_RUNTIME_IMAGE"
docker pull \
  "$CROSSFIRE_MIGRATION_IMAGE"
```

The registry manifest digest is not Docker's configuration ID or an exported
archive's root descriptor. The publisher verified each manifest's configuration
against the tested package, then pulled the immutable reference and checked
platform, backend, version and source labels. Existing version tags were not
overwritten. Cached layers were reused during pull verification; this is not a
cold-download throughput measurement.

The runtime and migration image must match release/source labels. Complete
initialization and Knex migration before server startup. The server never
migrates its database at startup and never starts native agents.
